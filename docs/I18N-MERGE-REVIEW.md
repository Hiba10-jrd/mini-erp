# Audit et correction i18n FR / EN / AR — 9 octobre 2026

Audit réalisé avant modification sur `test/merge-traduction`, merge non commité. Aucun commit, push, changement de main ou migration de base de données.

## Diagnostic avant correction

131 clés absentes : A=121, B=5, C=4, D=1, E=0. Catégories exclusives par décision de correction ; D désigne une phrase utilisateur contenant une référence technique à LOT 17.

Chaque JSON contient 1 475 entrées textuelles, mais seulement 1 354 clés uniques : 121 occurrences répétées par fichier. 39 occurrences répétées EN et 61 AR ont une valeur différente. La déduplication conserve la dernière valeur, donc le comportement effectif existant. Le rapport `I18N-AUDIT.md` préexistant confondait entrées et clés uniques.

Cause racine : constitution des catalogues par blocs, absence de validation complète des usages, vocabulaire non canonique et exemption des groupes PHP sans résolution des clés. Aucun conflit Git ne garantit la couverture i18n.

Les accords Validé/Validée, les contextes fournisseurs/clients, les conséquences stock et les placeholders sont conservés. Les descriptions historiques Réception :number restent disponibles : leur clé peut être persistée dans metadata.description_key. Les exceptions métier restent traduites ; les codes de statut et identifiants ne changent pas.

## Architecture et plan

Conserver le modèle JSON pendant ce correctif. Laravel supporte les deux modèles : https://laravel.com/framework/docs/12.x/localization. Introduire progressivement des clés PHP structurées pour les nouveaux messages d'un domaine, puis migrer domaine par domaine avec tests et alias pour les clés persistées ; ne pas migrer les descriptions historiques sans stratégie de compatibilité. Aucun déplacement vers PHP n'est nécessaire ici.

Les catégories B/C ci-dessous indiquent exactement les substitutions autorisées, limitées aux arguments littéraux de traduction. A indique une traduction nouvelle justifiée par son contexte. D conserve l'explication financière et enlève le numéro de lot. L'ancien texte grammaticalement erroné sur une ligne répétée garde sa clé pour compatibilité, mais sa valeur est corrigée.

Renforcer les contrôles : unicité JSON avant décodage, ensembles de clés indépendants de leur ordre, chaînes non vides, placeholders FR/EN/AR (y compris absence attendue), parité des catalogues PHP, résolution réelle sans fallback et extraction avec délimiteur/échappement corrects. Conserver trans_choice et vérifier les nombres arabes 0/1/2/3/11/100 ; ne pas modifier les règles Eloquent de pluralisation.

Gestion de locale auditée : session valide prioritaire, puis préférence utilisateur, puis configuration ; App et Carbon synchronisés. Route POST validée et protégée CSRF, persistance invité/session et utilisateur. Attributs lang/dir et CSS RTL conservés. Les tests existants couvrent ces parcours ; les priorités et les sessions invalides méritent également des tests ciblés.

UTF-8 valide, pas de caractère de remplacement U+FFFD dans les JSON. Le mojibake initial était produit par la lecture PowerShell sans -Encoding utf8. Les clés anglaises de Breeze sont compatibles Laravel et ne justifient pas une migration de tout le catalogue.

Risques d'un ajout brut : variations inutiles, doublons masqués par json_decode, dégradation du vocabulaire, contexte métier perdu, pluriels arabes incorrects et faux positifs du test PHP. Limites : contrôle statique des appels littéraux ; les clés dynamiques et l'exactitude linguistique de tout le catalogue demandent une revue complémentaire.
